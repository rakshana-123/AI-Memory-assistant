> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make all 24 pages (user panel + admin console) usable at any viewport (the user browses at ~607×614): no clipping/overlap, page scrolls when needed, scrollbars hidden, dev overlay gone, and the on-page interactive controls (search, tabs/filter pills, checkboxes, toggles, pagination) actually work — with zero visual change at desktop (≥1280px) vs the approved mockup builds.

**Architecture:** Same self-contained page files. A shared responsive recipe (Tailwind breakpoint variants layered onto the existing classes) and a shared interactivity recipe (client-side state/filtering of each page's existing mock data). No new dependencies, no shared component extraction, no invented UI (no new modals/toasts; mutating action buttons like Add/Export stay visual).

**Tech Stack:** unchanged (Next 16, Tailwind 4, lucide-react, recharts).

## Global Constraints

- **Desktop fidelity is frozen:** at ≥1280px wide (mockup viewport class), every page must render exactly as the already-approved builds. Responsive changes are ADDITIVE breakpoint variants (`lg:`/`xl:` prefixed copies of existing classes), never removals of the existing classes. The base (un-prefixed) classes stay as-is; new behavior applies BELOW the breakpoint via `max-lg:`/base+`lg:` overrides — pick the form that leaves the ≥lg outcome byte-identical.
- **Responsive recipe (apply to every page):**
  - Root wrapper `h-screen overflow-hidden` → `min-h-screen lg:h-screen lg:overflow-hidden` (page scrolls when content exceeds viewport on small screens; desktop unchanged). Inner `h-full`/`flex-1` columns get `lg:h-full`/`min-h-0` as needed so desktop keeps the fixed-viewport layout and small screens flow.
  - Fixed-width header inputs (`w-[400px]`, `w-[520px]`…) → `w-full max-w-[400px]` etc.
  - Multi-column content grids (`grid-cols-2/3/4`, `grid-cols-[...]`) → `grid-cols-1 <bp>:grid-cols-… lg:grid-cols-N` (collapse sensibly; keep the original N at lg+).
  - Side-by-side main+right-panel layouts: stack (`flex-col lg:flex-row` or grid collapse) below lg.
  - Tables and wide rows: wrap scroll container (`overflow-x-auto`) where not already, so they scroll instead of overlapping.
  - Fixed card/list heights that clip on small screens: `min-h-0` + natural flow below lg.
  - Sidebar stays visible at all sizes (it is the primary nav) but may collapse to icons below `sm` IF a page's markup allows it cleanly via existing classes — otherwise leave width as-is and let main content scroll horizontally-free. Do NOT build hamburger drawers.
- **Interactivity recipe (apply to every page where the control exists):**
  - Search inputs: `useState` query; filter the page's primary data array (title/name/label, case-insensitive `includes`); empty result shows the list area empty (no invented empty-states).
  - Tab bars / filter pills / segmented controls: `useState` active key; clicking sets active styling (reuse the file's existing active classes) and filters the associated list/table where a data relationship exists.
  - Table row checkboxes: controlled `checked` state (per-row id set or boolean map) — clicking toggles.
  - Toggle switches: `useState` boolean where a component already visualizes on/off; clicking flips (several pages already do this — leave working ones alone).
  - Pagination controls: `useState` page index slicing the visible rows; prev/next + page numbers functional; page-size from the existing data chunking.
  - NOT in scope (leave visually as-is): Add/New/Export/Save/Delete/kebab action buttons, dropdown selects without data relationships, cross-page navigation beyond the existing sidebar links. Do not build modals, toasts, drawers, or skeletons.
- **Hydration safety:** no `Math.random`/`Date.now`/`new Date` anywhere (seeded PRNG pattern only if randomness is ever needed).
- **No new dependencies.** `npm run build` exit 0 at the end of every task.
- Do not touch `admin/` or `refernce/`. Work on branch `feature/ui-polish` (from `main`). Commit per task.
- Existing per-page conventions preserved: `"use client";` line 1, aliased `NextLink` import, one default export.
